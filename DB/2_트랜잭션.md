# 2. 트랜잭션 (Transaction)

## **트랜잭션이란?**

트랜잭션이란, 하나의 논리적 작업 단위로 묶인 여러 연산의 집합이다. 가장 중요한 것은 전부 성공하거나 전부 실패하게 하는 것이다. 예시를 들면 바로 이해할 수 있다.

### **EX - 계좌이체를 하는 경우**

A가 B에게 만 원을 이체한다고 하자. 이건 두 개의 연산으로 이뤄진다.

```
1. A 계좌에서 만 원 차감
2. B 계좌에 만 원 추가
```

위 두 개의 동작은 하나로 묶여야 한다. 둘 중 하나만 성공하면 심각한 이슈가 된다. 이렇게 동작을 하나로 묶는 단위를 트랜잭션이라고 한다.

<br>

## **ACID - 트랜잭션의 4대 성질**

트랜잭션이 보장해야하는 4가지 성질의 앞글자를 따서 ACID라고 한다.

```
A - 원자성 (Atomicity)
C - 일관성 (Consistency)
I - 격리성 (Isolation)
D - 지속성 (Durability)
```

### **A - 원자성 (Atomicity)**

원자성은 트랜잭션 내의 연산들이 **모두 성공하거나 모두 실패**해야 한다는 성질이다. 즉, 트랜잭션이 중간에 실패하면 이전에 수행한 연산들을 모두 취소하고 처음 상태로 되돌린다. 이를 **롤백(Rollback)** 이라고 한다.

### **C - 일관성 (Consistency)**

일관성은 트랜잭션이 수행되기 전과 수행된 후의 데이터가 **항상 일관된 상태**를 유지해야 한다는 성질이다. 즉, 트랜잭션이 성공적으로 완료되면 데이터베이스는 항상 유효한 상태를 유지해야 한다.

예를 들어 "계좌 잔액은 음수가 될 수 없다"는 규칙이 있으면, 트랜잭션이 끝난 뒤에도 이 규칙이 지켜져야 한다.

즉, 트랜잭션이 데이터를 바꾸더라도, **DB가 정의한 무결성 제약(타입, 키, 조건 등)을 깨뜨리지 않는 상태를 유지**하는 것이다.

### **I - 격리성 (Isolation)**

격리성은 동시에 여러 트랜잭션이 수행될 때, 서로의 연산이 **간섭하지 않아야 한다**는 성질이다. 즉, 한 트랜잭션이 수행되는 동안 다른 트랜잭션은 그 트랜잭션의 중간 상태를 볼 수 없어야 한다.

다만, 완벽하게 지켜지면 성능이 떨어져서 실무에서는 격리수준을 조절한다.

### **D - 지속성 (Durability)**

지속성은 트랜잭션이 성공적으로 완료되면, 그 결과가 **영구적으로 저장**되어야 한다는 성질이다. 즉, 시스템이 갑자기 다운되거나 장애가 발생하더라도, 이미 커밋된 트랜잭션의 결과는 손실되지 않고 유지되어야 한다.

이를 위해 DB는 커밋된 내용을 **디스크에 로그로 기록**해둔다. (MySQL의 Redo 로그가 이 역할을 한다)

<br>

## **커밋 / 롤백**

트랜잭션의 결과를 확정하거나 취소하는 명령이다.

- **커밋 (Commit)** : 트랜잭션의 **모든 연산이 성공적으로 완료**되었음을 확정하고, 변경 내용을 **영구적으로 반영**한다.
- **롤백 (Rollback)** : 트랜잭션의 모든 변경을 취소하고 **시작 이전 상태로 되돌리**는 것이다. 중간에 오류가 나거나 문제가 생기면 롤백한다. **(원자성 보장)**

<br>

## **트랜잭션의 상태**

트랜잭션이 거치는 상태를 보면 다음과 같다.

```
활동(Active) → 연산 실행 중
     ↓
부분 완료(Partially Committed) → 마지막 연산까지 실행됨, 커밋 직전
     ↓
   ┌─────┴─────┐
완료(Committed)   실패(Failed)
결과 확정          → 철회(Aborted), 롤백됨
```
