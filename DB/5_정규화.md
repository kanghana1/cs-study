# 5. 정규화 (Normalization)

## **정규화란?**

정규화는 데이터의 **중복을 최소화** 하도록 테이블을 구조화하는 과정이다.

### **중복을 제거해야 하는 이유**

정규화가 왜 필요한지 이해하려면, 중복이 왜 문제인지를 알아야 한다. 예를 들어 아래와 같은 테이블이 있다고 가정해보자.

```
수강 테이블
┌──────┬────────┬────────┬──────────┐
│학생ID│ 학생이름│ 과목   │ 교수명   │
├──────┼────────┼────────┼──────────┤
│  1   │ 하나   │ DB     │ 김교수   │
│  1   │ 하나   │ 알고리즘│ 이교수   │
│  2   │ 두나   │ DB     │ 김교수   │
└──────┴────────┴────────┴──────────┘
```

여기서 문제는 같은 이름이 여러 번 나오고, 특정 과목 - 특정 교수의 조합이 반복된다. 이러한 중복은 이상현상을 일으킨다.

### **이상 현상 (Anomaly)**

중복이 있는 테이블에서 데이터를 조작할 때 생기는 문제를 이상현상이라고 부른다. 이는 3가지가 있다.

#### **1. 삽입 이상 (Insertion Anomaly)**

원하지 않는 불필요한 데이터까지 넣어야하는 문제이다.

```
새 과목 "네트워크-박교수"를 등록하고 싶은데,
아직 수강하는 학생이 없음
        ↓
그런데 이 테이블은 학생ID가 있어야 행을 넣을 수 있음
        ↓
학생이 없으면 과목 정보만 따로 넣을 수가 없음! (또는 학생ID를 비워야 함)
```

과목 정보를 넣으려는데 학생 정보가 꼭 필요해서, 학생 없이는 과목을 등록 못 하는 상황이 생긴다.

#### **2. 갱신 이상 (Update Anomaly)**

중복된 데이터 중 일부만 바뀌어 불일치가 생기는 문제이다.

```
"DB" 과목의 교수가 김교수 → 최교수로 바뀜
        ↓
DB 과목이 있는 모든 행을 다 바꿔야 함
        ↓
하나라도 빠뜨리면 → 어떤 행은 김교수, 어떤 행은 최교수 (데이터 불일치!)
```

같은 정보가 여러 곳에 중복되어 있어서 수정할 때 전부 다 바꾸어야 한다.

#### **3. 삭제 이상 (Deletion Anomaly)**

삭제 이상은 특정 데이터를 삭제했을 때, 원하지 않는 데이터까지 같이 삭제되는 문제이다.

```
두나가 DB 수강을 취소해서 그 행을 삭제
        ↓
근데 그 행이 "DB 과목은 김교수가 가르친다"는 유일한 기록이었다면
        ↓
학생 정보를 지웠는데 과목·교수 정보까지 날아감!
```

학생의 수강기록을 지웠을 뿐인데, 과목이나 교수 정보까지 딸려 사라진다.

위 세 가지 문제가 모두 중복으로 인한 문제이다.

## **정규화 단계**

정규화는 단계별로 진행된다.

### **1NF (제1정규형)**

1NF는 **모든 칼럼이 원자값(Atomic Value)을 가져야 한다**는 조건이다. 즉, 칼럼에 여러 값이 들어가면 안 된다.

```
위반 ❌
┌──────┬──────────────┐
│학생  │ 수강과목     │
├──────┼──────────────┤
│하나  │ DB, 알고리즘 │ ← 한 칸에 값 2개!
└──────┴──────────────┘

1NF 만족 ⭕
┌──────┬──────────┐
│학생  │ 수강과목 │
├──────┼──────────┤
│하나  │ DB       │
│하나  │ 알고리즘 │ ← 행을 나눔
└──────┴──────────┘
```

### **2NF (제2정규형)**

1NF를 만족하면서 기본키의 **일부에만 종속되는 칼럼을 제거**한다.

복합키일 때 생기는 문제이며, 복합키의 일부에만 속한 칼럼을 분리하는 것이다.

```
PK = (학생ID, 과목)  ← 복합키
┌──────┬──────┬────────┬────────┐
│학생ID│ 과목 │ 학생이름│ 성적   │
└──────┴──────┴────────┴────────┘

문제: "학생이름"은 (학생ID, 과목) 전체가 아니라
      "학생ID"에만 종속됨 (부분 종속)
      → 과목이 뭐든 학생ID가 같으면 이름은 같으니까

해결: 학생 정보를 분리
학생 테이블 (학생ID → 학생이름)
수강 테이블 (학생ID, 과목 → 성적)
```

위 예시에서 성적은 둘 다 있어야 정해지지만, 학생이름은 학생ID만으로 정해진다. 이런 칼럼을 떼어내는 것이 2NF이다.

### **3NF (제3정규형)**

3NF는 2NF를 만족하면서 **기본키가 아닌 칼럼이 다른 기본키가 아닌 칼럼에 종속되지 않아야 한다**는 조건이다.

즉, **이행종속을 제거**하는 것이다.

```
┌──────┬────────┬──────────┐
│학생ID│ 학과   │ 학과사무실│
└──────┴────────┴──────────┘

종속 관계:
학생ID → 학과 → 학과사무실
         (학과가 정해지면 사무실이 정해짐)

문제: "학과사무실"은 학생ID에 직접 종속이 아니라
      "학과"를 거쳐서 간접 종속됨 (이행 종속)

해결: 학과 정보를 분리
학생 테이블 (학생ID → 학과)
학과 테이블 (학과 → 학과사무실)
```

이 외에도 BCNF, 4NF, 5NF가 있지만, 보통은 3NF까지를 목표로 한다.

## **반정규화란? (Denormalization)**

반정규화는 일부러 정규화를 거슬러 중복을 허용하는 것이다.

### **반정규화를 하는 이유**

중복을 제거하고 테이블을 분리할수록 JOIN 비용이 발생한다. JOIN을 많이 할수록 조회 성능이 떨어질 수 있다.

그래서 조회 성능이 중요한 경우, 일부러 중복을 허용해 JOIN을 줄이는 것이 반정규화이다.

```
예: 주문 테이블에 "회원이름"을 중복 저장
→ 원래는 회원 테이블과 JOIN해야 이름을 알 수 있음
→ 자주 조회된다면, 주문 테이블에 이름을 복사해두면 JOIN 없이 바로 조회
```

반정규화를 하면 중복에서 오는 이상현상을 감당해야 하기 때문에, 보통 **설계는 정규화로 하고 성능 병목이 발생하는 경우 해당 부분만 반정규화**를 한다.
