# 3. 격리 수준 (Isolation Level)

## **격리수준이란**

격리 수준은 여러 트랜잭션이 동시에 실행될 때 서로 얼마나 격리할지 정하는 단계이다.

앞서 배운 트랜잭션의 4가지 요건 ACID 중 격리성을 완벽하게 지키려면, 결국은 **직렬화를 통해 하나씩 순서대로 진행**을 하게되고 대기가 쌓여 **처리량이 떨어**질 수 있다.

그래서 DB는 격리 정도를 4단계로 나누어 개발자가 상황에 맞게 고를 수 있도록 했다.

```
낮은 격리 → 성능 ↑, 데이터 이상 위험 ↑
높은 격리 → 성능 ↓, 데이터 안전 ↑
```

격리성을 낮출수록 여러 트랜잭션이 자유롭게 섞여 빠르지만 그만큼 이상현상이 생길 위험이 있다. 여기서 이상현상은 무엇일까?

<br>

## **동시성 이상현상**

격리를 느슨하게 했을 때 대표적으로 발생할 수 있는 이상현상은 다음과 같다.

### **Dirty Read**

Dirty Read는 **아직 커밋되지 않은 다른 트랜잭션의 데이터를 읽는 것**을 말한다.

```
트랜잭션A: 계좌 잔액을 10000 → 50000 으로 수정 (아직 커밋 안 함)
        ↓
트랜잭션B: A가 수정한 50000을 읽음 ← 아직 확정 안 된 값!
        ↓
트랜잭션A: 문제가 생겨서 롤백 (다시 10000으로)
        ↓
결과: B는 존재하지도 않는 50000을 읽어버린 것
```

아직 확정되지 않은 값을 읽는 것이다.

### **Non-Repeatable Read (반복 불가능 읽기)**

Non-Repeatable Read는 **트랜잭션이 같은 데이터를 두 번 읽었을 때, 다른 트랜잭션이 그 사이에 데이터를 수정해서 값이 달라지는 것**을 말한다.

```
트랜잭션A: 잔액 조회 → 10000
        ↓
트랜잭션B: 잔액을 20000으로 수정하고 커밋
        ↓
트랜잭션A: 같은 잔액 다시 조회 → 20000  ← 아까랑 다름!
```

이렇게 두 번의 읽기 결과가 달라진다.

### **Phantom Read (팬텀 읽기)**

Phantom Read는 **트랜잭션이 같은 조건으로 데이터를 조회했는데, 다른 트랜잭션이 그 사이에 새로운 데이터를 추가하거나 삭제해서 결과가 달라지는 것**을 말한다.

```
트랜잭션A: "나이 20세 이상" 조회 → 5명
        ↓
트랜잭션B: 25세 회원 1명 INSERT하고 커밋
        ↓
트랜잭션A: 같은 "나이 20세 이상" 다시 조회 → 6명  ← 유령처럼 한 명 생김!
```

Non-Repeatable Read는 기존 행의 값이 바뀌는 거고, Phantom Read는 행의 개수 자체가 바뀌는 거다. 없던 행이 유령(phantom)처럼 나타난다.

<br>

## **격리 수준 4단계**

이제 이 이상현상들을 어디까지 막느냐에 따라 4단계로 나뉜다.

### **Read Uncommitted**

Read Uncommitted는 가장 낮은 격리 수준으로, **커밋되지 않은 데이터도 읽을 수 있는 수준**이다. 즉, **Dirty Read가 발생**할 수 있다.

성능은 가장 좋을 수 있지만 위험해서 실무에서 거의 사용하지 않는다.

### **Read Committed**

Read Committed는 **커밋된 데이터만 읽을 수 있는 수준**이다. 즉, Dirty Read는 발생하지 않는다. 하지만 **Non-Repeatable Read는 여전히 발생**할 수 있다.

### **Repeatable Read**

Repeatable Read는 **같은 데이터를 반복해서 읽을 때 항상 같은 값을 보장**하는 수준이다. 즉, Dirty Read와 Non-Repeatable Read는 발생하지 않는다. 하지만 **Phantom Read는 발생**할 수 있다.

자주 사용되는 MySQL의 기본 격리 수준이 바로 Repeatable Read이다. 특이하게 MySQL InnoDB는 이 수준에서 Phantom Read까지 상당 부분 막아준다! 이는 **MVCC**라는 기술 덕분인데, 아래에 나온다.

### **Serializable**

Serializable은 가장 높은 격리 수준으로, **모든 이상현상이 발생하지 않도록 완벽하게 격리**하는 수준이다. 즉, Dirty Read, Non-Repeatable Read, Phantom Read 모두 발생하지 않는다.

그러나 사실상 줄세워서 실행하는 거라 동시성이 거의 없어져 성능이 가장 안 좋다.

<br>

## **MVCC (Multi-Version Concurrency Control, 다중 버전 동시성 제어)**

MVCC는 **동시에 여러 트랜잭션이 수행될 때, 서로 간섭하지 않고 동시에 수행할 수 있도록 하는 기술**이다.

데이터를 수정할 때 원본을 바로 덮어쓰지 않고 새 버전을 만드는 방식을 사용한다. 이렇게 하면 트랜잭션은 자신이 시작한 시점의 버전만 보기 때문에, 다른 트랜잭션이 쓰기 작업을 해도 옛날 버전이 보인다.

### **Undo Log (언두로그)**

Undo Log는 **트랜잭션이 수행되기 전의 데이터를 저장**하는 로그이다. 트랜잭션이 롤백되면 Undo Log를 이용해 이전 상태로 되돌린다. 또, 데이터가 수정되면 변경 전 값을 언두 로그에 백업해둔다!
