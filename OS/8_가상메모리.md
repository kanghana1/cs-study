# 8. 가상 메모리

## **1. 가상 메모리란?**

<br>

### **가상 메모리가 필요한 이유**

프로세스를 실행하려면 메모리에 올려야 한다. 그런데 우리는 어떤 프로그램에서 일부의 기능을 사용할 뿐, 전체를 사용하지 않는데도 메모리에 다 올라가야 할 필요가 있을까? 사용하지 않는 것들까지 올리는 건 메모리 낭비이다.

이렇게 **당장 필요한 부분만 메모리에 올리고, 나머지는 디스크에 두는 것**이 가상메모리의 핵심 아이디어이다.

<br>

### **가상 메모리란 무엇일까**

가상 메모리는 **프로세스 전체를 메모리에 올리지 않고도 실행할 수 있게 해주는 기법**이다.

일부만 물리 메모리에 두고, 나머지는 디스크에 두어 프로세스가 착각하게 만든다.

이게 가능한 이유는, 프로그램이 메모리를 쓰는 패턴에 규칙성이 있기 때문이다. 이를 **지역성**이라고 한다.

<br>

**시간적 지역성 (Temporal Locality)**

한 번 쓴 데이터를 곧 다시 쓸 가능성이 높다는 이론

**공간적 지역성 (Spatial Locality)**

한 번 접근한 데이터 근처를 곧 접근할 가능성이 높다는 이론

<br>

이러한 지역성 떄문에, 특정 시점에 일부 영역만 집중적으로 쓰게 되고, 그 부분만 메모리에 올려두면 대부분의 작업이 처리된다.

<br>

### **가상 메모리의 장점**

**1. 물리 메모리보다 더 큰 프로그램을 실행할 수 있다**

**2. 더 많은 프로세스를 동시에 올릴 수 있다**

- 같은 메모리에 더 많은 프로세스가 들어감
- 멀티프로그래밍 정도가 높아짐

<br>

가상 메모리를 사용하는 경우, 프로세스 전체를 메모리에 올리는 것이 아니기 때문에, **메모리에 올라와있지 않은 부분에 접근**하게 될 수 있다.

이 경우, 가상 메모리 구현 방식에 따라 바로바로 디스크에서 가져올 수도 있고, 사용을 예측해서 미리 디스크에서 메모리로 올리기도 한다. 이를 각각 **요구 페이징**과 **선반입** 이라고 한다.

<br>

## **2. 요구 페이징(Demand Paging)과 페이지 폴트(Page Fault)**

<br>

### **요구 페이징 (Demand Paging)**

**요구 페이징**은 필요한 페이지를 **미리 올려두지 않고 그때 그때 메모리에 올려두는 방식**이다.

프로세스가 시작할 때 아무것도 안 올리거나, 최소한만 올려두고, 실제로 그 페이지에 접근할 때 디스크에서 가져온다. 이때 페이지 폴트라는 개념이 나온다.

<br>

### **페이지 폴트 (Page Fault)**

프로세스가 어떤 이미지에 접근했는데, 그 페이지가 아직 물리메모리에 없는 상황이다.

```
🔗 처리과정
1. 프로세스가 페이지에 접근
2. 페이지 테이블 확인 → 메모리에 없음! (페이지 폴트 발생)
3. OS가 개입 → 디스크에서 해당 페이지를 찾음
4. 빈 프레임에 페이지를 올림
5. 페이지 테이블 갱신 (이제 메모리에 있다고 표시)
6. 중단됐던 작업을 다시 실행
```

위 처리과정에서 3,4번은 디스크 접근인데, 디스크는 메모리보다 수만배 느리기 때문에, **페이지 폴트가 발생하면 처리비용이 굉장히 크다. -> 부하 발생**

페이지가 메모리에 있는지를 구분하기 위해 **페이지 테이블에 유효비트 (Valid / Invalid)**를 둔다.

```
페이지 테이블
┌────────┬─────────┬──────────┐
│ 페이지 │ 프레임  │ 유효비트 │
├────────┼─────────┼──────────┤
│   0    │    1    │    v     │ ← 메모리에 있음
│   1    │    -    │    i     │ ← 메모리에 없음 (디스크에)
│   2    │    4    │    v     │ ← 메모리에 있음
└────────┴─────────┴──────────┘
```

프로세스 시작 초기에는 메모리에 올라와있는 게 적기 때문에 페이지 폴트가 많이 발생한다. 이를 **콜드 스타트 (Cold Start)** 라고 한다.

메모리가 다 찼는데 페이지 폴트가 발생한 경우에는 **페이지 교체**가 일어난다.

<br>

### **페이지 교체 (Page Replacement)**

빈 프레임이 없을 때 메모리에 있는 페이지 중 하나를 골라 디스크로 내보내고 그 자리를 확보하는 것을 의미한다. 이때 내보내지는 페이지를 **희생자 페이지**라고 한다.

이때, 누구를 희생자 페이지로 할 것인지 잘 결정해야 페이지 폴트를 최소화하여 부하를 줄일 수 있다.

<br>

## **페이지 교체 알고리즘**

페이지 교체 알고리즘에는 여러가지가 있다.

### **1. FIFO (First In First Out)**

가장 먼저 메모리에 올라온 페이지를 내보내는 방식이다. 구현 방식이 가장 단순하지만, 먼저 올라온 페이지가 안 쓰는 페이지는 아니기 때문에, 효율이 좋지 않다.

> **🔗 Belady's Anomaly (벨라디의 역설)**
>
> 프레임 (메모리 공간) 를 늘리면 더 많은 페이지를 담아둘 수 있기 때문에 페이지 폴트는 줄어드는 게 상식적이다.
>
> 그러나, FIFO를 사용하는 경우 이 상식이 깨질 때가 있다. **프레임을 늘렸지만 페이지 폴트가 오히려 늘어나느 것**이다! 이러한 현상을 **벨라디의 역설**이라고 부른다.
>
> 이러한 일이 일어나는 이유는 두 가지이다.
>
> - FIFO는 먼저 들어온 순서만 보기에 곧 다시 쓸 페이지를 내보내는 일이 생긴다.
> - 프레임 수가 바뀌면 **쫓겨나는 순서도 통째로 바뀐다.** 프레임이 늘어나면 페이지가 메모리에 더 오래 머무는데, 하필 그 바람에 정작 곧 필요한 페이지가 쫓겨나기 직전 타이밍에 걸려버리는 경우가 생기는 것이다.

### **2. OPT (Optimal)**

앞으로 가장 오랫동안 안 쓸 페이지를 내보낸다. 이론상 최적이고 페이지 폴트가 가장 적다.

최적이긴 하지만, 미래를 알아야 한다. 따라서 현실에서 구현이 불가능한 방법이며, 대신 다른 알고리즘이 얼마나 좋은지 비교하는 기준이 된다.

### **3. 🌟 LRU (Least Recently Used)**

**가장 오래 안 쓰인 페이지**를 내보낸다. OPT가 미래를 보는 거라면, LRU는 과거를 봄으로써 최근에 안 쓴 페이지를 앞으로도 쓰지 않을 것이라 예상하는 알고리즘이다. 즉, **시간 지역성을 활용**한 알고리즘이다.

그러나, 마지막으로 언제 썼는지 기록해야 하기 때문에 구현 비용이 든다.

그래서! 시간 기록으로 발생하는 부하를 줄이기 위해 최근에 썼는지 여부만 1bit로 표시한다. 이를 **참조 비트**라고 한다.

```
페이지를 참조(사용)하면 → 참조 비트를 1로
일정 주기마다 OS가     → 모든 참조 비트를 0으로 초기화
```

이 참조비트를 활용한 대표적인 방식에는 Clock 알고리즘이 있다.

> **🔗 Clock 알고리즘 (Second Chance)**
>
> 페이지를 원형으로 배치하고 시곗바늘같은 포인터가 돌아가며 희생자를 고륻다.
>
> **참조 비트가 0** : 최근에 안 썼으므로 희생자로 선택
>
> **참조 비트가 1** : 최근에 썼으니 참조 비트를 0으로 바꾸고 바늘을 다음으로 넘김. 즉 두 번의 기회가 부여되는 셈
>
> 정확도는 떨어질 수 있으나, 가벼워서 이 방식을 많이 쓴다.

<br>

### **4. LFU (Least Frequently Used)**

**참조된 횟수가 가장 적은 페이지**를 내보낸다. LRU가 언제 썼는지를 본다면, LFU는 얼마나 썼는지를 본다.

이 경우, 잠깐 많이 쓰이고, 그 뒤로 안 쓰이는 페이지가 횟수만 높아서 계속 남는 문제가 있다.

### **5. MFU (Most Frequently Used)**

반대로 가장 많이 참조된 페이지를 내보낸다. 충분히 썼으니 내보내는 방식인데, 직관과 반대라 잘 사용하지 않는다.
