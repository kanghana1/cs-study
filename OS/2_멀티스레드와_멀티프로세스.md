# 2. 멀티스레드과 멀티프로세스

## ✅ 멀티스레드

멀티 스레드는 하나의 프로그램 안에서 여러 스레드를 실행하는 것을 의미한다. 프로세스를 이용해 동시에 처리하던 일을 스레드로 구현하게 되면 **메모리 공간과 시스템 자원을 공유**해서 사용하기 때문에 자원 소모가 줄어든다.

스레드 간 통신이 필요할 때에도 별도의 자원을 이용하는 것이 아니라 전역 변수 공간이나 동적 할당 공간 (Heap 영역) 을 이용해 데이터를 주고받을 수 있다.

그렇기 때문에 프로세스 간 통신에 비해 스레드 간 통신이 훨씬 간단하다. 게다가 스레드의 Context Switching은 프로세스 Context Swiching과 달리 **캐시 메모리를 비울 필요가 없어 빠르**기까지 하다.

결과적으로 시스템의 throughput(일정 시간동안 처리하는 데이터의 양)이 향상되고, 자원 소모가 줄어들어 자연스레 프로그램 응답 시간을 단축할 수 있다.

당연히 문제점도 있다. **서로 다른 스레드끼리 데이터, 힙 영역을 공유**하기 때문에 동일한 자원에 **동시에 접근**하여 엉뚱한 값을 읽거나 수정하는 경우가 생긴다.

이러한 이유로 멀티스레딩 환경에서는 **동기화 작업**이 필요하다. 동기화를 통해 작업 순서를 컨트롤하고 동시 접근을 컨트롤할 수 있다. 하지만 동기화로 인해 **병목 현상**이 생길 수 있고, 자연스럽게 **성능이 저하**될 가능성이 높다.

<br>

## ✅ 멀티스레드 vs 멀티프로세스

### 멀티스레드

- 메모리 공간 차지가 적고 Context Switching이 빠르다
- 하나의 스레드가 오류나면 프로세스 내 전체 스레드가 종료될 수 있다
- 동기화가 필요하다 (병목이 생길 수 있다)

### 멀티프로세스

- 하나의 프로세스가 죽더라도 다른 프로세스에 영향을 주지 않는다
- 멀티스레드보다 많은 메모리와 CPU 시간을 차지한다
