# 2. 애플리케이션 계층 (Application Layer)

## **애플리케이션 계층이란?**

애플리케이션 계층은 응용계층이라고도 하며, 사용자와 가장 가까운 계층이다.

우리가 쓰는 웹브라우저, 이메일, 카카오톡 같은 프로그램들이 이 계층에서 동작하며, 사용자의 요청을 처리하는 프로토콜들이 이 계층에 있다.

애플리케이션 계층은 **무엇을 주고받을지 즉, 내용과 형식을 정의**한다. 어떻게 안전하게 전달할지는 여기서 정하지 않는다.

<br>

## **HTTP 기초**

### **HTTP (HyperText Transfer Protocol)란,**

웹에서 **클라이언트와 서버가 데이터를 주고받는 규칙**이다. 기본 구조는 요청과 응답으로 이루어진다.

클라이언트가 먼저 요청하면 서버가 요청에 대해 응답하는 구조이며, 항상 **클라이언트가 먼저 시작**한다는 특징이 있다.

<br>

### **HTTP 특징**

HTTP는 두가지 큰 특징이 있다.

**✔️ Stateless (무상태성)**

HTTP는 각 요청을 **독립적으로 처리**하며, 이전 요청을 기억하지 않는다.

그렇기 때문에 방금 로그인을 했어도 다음 요청에서는 해당 클라이언트를 기억하지 못해 로그인 유지를 위해 토큰, 쿠키, 세션 등을 사용한다.

대신 HTTP가 stateless한 덕분에, **서버가 상태저장을 하지 않아 부담이 적고 확장이 쉽다.**

**✔️ Connectionless (비연결성)**

HTTP는 요청과 응답이 끝나면 연결을 끊는다. 이 또한 서버 자원을 아끼기 위해서 연결을 끊는다.

> **🔗 HTTP의 keep-alive**
>
> HTTP 버전이 올라가면서 keep-alive로 비연결성을 개선했다.
>
> 웹페이지 하나를 띄우려면 수많은 HTML파일, CSS, js파일 등이 필요한데 이를 각각 연결하고 끊으면 비용이 많이 들고 성능도 안 좋아진다. 이를 해결하기 위해 나온게 keep-alive이다.
>
> keep-alive는 한 번 연결을 맺으면 끊지 않고 유지해 재사용한다. 일정시간 요청이 없다면 연결을 끊고, 요청이 있다면 재사용하는 방식으로 동작한다.

<br>

## **DNS (Domain Name Server)**

우리는 보통 모든 사이트의 IP 주소를 외우지 않는다. Naver에 들어갈 때에도 naver.com을 치지, 네이버에서 사용하는 IP 주소를 치지 않는다는 의미이다.

그런데 컴퓨터는 IP 주소로만 통신한다. 그래서 **이름을 IP 주소로 바꿔주는 시스템**이 필요한데 이 역할을 하는게 **DNS**이다.

<br>

### **DNS란**

DNS는 도메인 이름을 IP 주소로 변환해주는 시스템이다. 그럼 전세계 수십억개의 도메인을 어떻게 저장하고 있는걸까?
한 곳에 저장은 당연히 불가능하기 때문에, 계층적으로 분산해서 관리한다.

<br>

### **DNS 계층구조**

DNS서버는 역할에 따라 여러 종류로 나뉜다.

```
1. Root DNS 서버 (최상위)
        ↓  "com은 저쪽에 물어봐"
2. TLD DNS 서버 (Top-Level Domain, .com/.org/.kr 등 관리)
        ↓  "google.com은 저쪽에 물어봐"
3. Authoritative DNS 서버 (실제 IP를 알고 있는 최종 서버)
        ↓  "google.com은 142.250.207.46 이야!"
```

그런데 똑같은 사이트를 갈 때마다 이 전체 과정을 반복하면 비효율적이다. 그래서 캐싱을 한다!

> **캐시 (Caching)**
>
> 한 번 알아낸 DN -> IP 결과를 캐시에 저장해둔다.
>
> - 브라우저 캐시 : 브라우저가 최근 방문한 도메인의 IP를 기억함
> - OS 캐시 : 운영체제도 따로 저장
> - Local DNS 캐시 : Resolver도 따로 저장해둬서 다른 사람이 같은 도메인을 물으면 바로 응답함
>
> 위 캐시들이 모두 Miss 인 경우 전체 과정을 밟는다.

<br>

## **SMTP (+ POP3/IMAP)**

SMTP, POP3, IMAP 모두 이메일과 관련한 프로토콜이다. 역할에 따라서 두 종류로 나눌 수 있다.

- 메일 송신 : SMTP
- 메일 수신 : POP3 혹은 IMAP

한 개씩 알아보자.

<br>

### **SMTP (Simple Mail Transfer Protocol)**

SMTP는 이메일을 보내는 프로토콜이다. 이메일을 보내는 클라이언트와, 이메일을 받는 서버 사이에서 동작한다. 이 프로토콜은 두 군데에서 쓰인다.

- 내가 메일서버로 보낼때
- 메일서버끼리 주고받을때

메일서버는 도메인별로 존재하기때문에 다른 도메인간 메일전송도 가능하다. 같은 도메인간 전송의 경우 DNS 조회를 생략할 수 있다!

```
[내 메일앱]
    │ SMTP (보내기)
    ▼
[보내는 메일 서버]
    │ SMTP (서버 간 전달)
    ▼
[받는 메일 서버]  ← 여기까지가 SMTP의 영역
    │
    │ 여기서부터는 POP3/IMAP (받기)
    ▼
[상대방 메일앱]

```

<br>

### **POP3 & IMAP**

POP3과 IMAP은 받는 사람이 자기 메일 서버(우편함)에서 메일을 꺼내오는 프로토콜이다.

**POP3 (Post Office Protocol 3)**

메일을 내 기기로 다운로드하고, 서버에서는 삭제한다.

- **장점**
  - **서버 저장공간**을 아낌
  - 내 기기에 저장되기 때문에 오프라인에서도 볼 수 있음
- **단점**
  - 여러 기기에서 보기 힘듦 (서버에서 사라져서 폰에서 받은경우 PC에서 볼 수 없음)

<br>

**IMAP (Internet Message Access Protocol)**

메일을 서버에 그대로 두고, 동기화해서 보는 방식이다. 원본은 서버에 있고 내용만 확인한다.

- **장점**
  - 여러 기기에서 동일하게 볼 수 있음
  - 폰에서 읽음 처리하면 PC에서도 읽음으로 보임
- **단점**
  - 서버 저장공간을 계속 씀

<br>

요즘은 여러 기기에서 보기 때문에 IMAP을 많이 사용한다.
