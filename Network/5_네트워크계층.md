# 5. 네트워크 계층 (Network Layer)

## **네트워크 계층이란?**

네트워크 계층의 역할은 **목적지 호스트까지 데이터를 전달**하는 것이다.

```
네트워크 계층 → 어느 컴퓨터로 보낼지 (IP 주소로 호스트 찾기)
전송 계층     → 그 안의 어느 프로그램으로 (포트로 프로세스 찾기)
```

핵심기능은 다음과 같다.

- **주소지정**
  - 각 컴퓨터에 고유한 주소 (IP) 를 부여해서 식별
- **라우팅**
  - 출발지에서 목적지까지 데이터가 지나갈 경로를 지정

## **IP 주소체계**

### **IP주소란,**

IP 주소는 **네트워크 상에서 각 컴퓨터를 식별하는 고유 주소**이다. 편지의 집 주소와 같은 역할을 하며, 데이터를 보낼 때 이 주소를 보고 목적지를 찾아간다.

IP 주소에는 IPv4와 IPv6 두 가지 버전이 있다.

- IPv4
  - 가장 널리 사용하고 있는 방식
  - 32비트로 주소 표현 ex| 192.168.0.1
  - 43억개 정도만 표현 가능해서 이제 주소가 부족해짐
- IPv6
  - IPv4의 주소 부족을 해결하기 위한 방식
  - 128비트로 주소 표현 ex| 2001:0db8:85a3:0000:0000:8a2e:0370:7334
  - 사실상 무한개 표현 가능

### **공인IP vs 사설IP**

**공인IP**는 인터넷 상에서 **유일하게 부여되는 IP 주소**로, 전 세계 어디서든 접근 가능하다. **ISP가 할당**한다.

**사설IP**는 **공인IP를 가진 공유기 내부에서만 유일한 IP 주소**로, 외부에서는 접근 불가하다. 즉, **특정 내부 네트워크(LAN) 안에서만 쓰는 주소**이다. **공유기가 할당**한다. 이는 대역이 정해져있다.

```
사설 IP 대역 (내부에서만 사용)
10.0.0.0    ~ 10.255.255.255
172.16.0.0  ~ 172.31.255.255
192.168.0.0 ~ 192.168.255.255
```

구조는 다음과 같다.

```
구조를 보면
인터넷 ←── [공유기: 공인 IP 1개] ──→ 내부 기기들 (사설 IP 각각)
                                      192.168.0.2 (노트북)
                                      192.168.0.3 (폰)
                                      192.168.0.4 (TV)
```

각각의 기기가 사설 IP를 갖고, 밖으로 나갈 때에는 공유기의 공인 IP를 공유하는 구조이다. 이렇게 주소 부족 문제를 완화할 수 있게 된다.

여기서 생기는 문제는 밖에서 응답이 돌아올 때 **어느 기기를 대상으로 보내는지 알 수 없다는 것**이다. 이를 해결하는 것이 **NAT**이다.

<br>

## **서브넷 (Subnet)**

NAT를 알기 전에, 서브넷을 먼저 알아야 한다.

### **서브넷과 서브넷마스크**

**서브넷(Subnet)** 은 하나의 큰 네트워크를 더 **작은 네트워크로 나눈 것**이다. 큰 IP 대역을 잘게 쪼개서 **관리 효율과 보안**을 높인다.

이때, **어디까지가 네트워크 부분이고 어디부터가 호스트 부분인지 구분**해주는 게 **서브넷 마스크(Subnet Mask)** 다.

```
IP:          192.168.0.1
서브넷 마스크: 255.255.255.0

마스크가 255인 부분 = 네트워크 (192.168.0)
마스크가 0인 부분   = 호스트 (1)
```

이를 아래처럼 간단히 표시할 수 있고, 이를 **CIDR 표기법**이라고 부른다.

```
192.168.0.1/24
```

/24는 32비트 중 앞 24비트가 네트워크라는 뜻이다. 그러면 나머지 8비트가 호스트 몫이라, 이 서브넷 안에 약 254개의 기기를 둘 수 있다.

<br>

## **NAT (Network Address Translation)**

NAT는 **사설 IP와 공인 IP를 서로 변환**해주는 기술이다. 동작 방식은 다음과 같다.

```
1. 노트북(192.168.0.2)이 요청을 보냄
        ↓
2. 공유기가 출발지 주소를 자기 공인 IP로 바꿈
   192.168.0.2 → 공인IP(1.2.3.4)로 변환 (NAT)
   그리고 "이 요청은 노트북 거였다"고 기록해둠
        ↓
3. 공인 IP로 인터넷에 나감 → 서버가 응답
        ↓
4. 응답이 공유기의 공인 IP로 돌아옴
        ↓
5. 공유기가 기록을 보고 "이건 노트북 거였지" → 노트북으로 전달
   공인IP(1.2.3.4) → 192.168.0.2로 다시 변환
```

즉, 매핑 테이블을 관리하는 방식이다. 그런데, 여러 기기가 동시에 인터넷을 쓴다면 공인 IP 하나로 어떻게 구분할까? 이때 나온 개념이 PAT이다.

<br>

### **PAT (Port Address Translation)**

PAT는 **포트 번호까지 이용해서 사설 IP를 공인 IP로 변환**하는 기술이다. 즉, **같은 공인 IP를 쓰더라도 포트 번호를 다르게 해서 구분**하는 것이다.

```
노트북(192.168.0.2) → 공인IP:50001 로 매핑
폰(192.168.0.3)    → 공인IP:50002 로 매핑
TV(192.168.0.4)    → 공인IP:50003 로 매핑
```

외부에서 내부로 응답을 보낼 때에는 이렇게 포트번호로 구분하고, 이 포트번호를 보고 NAT에서 내부 IP로 변환해 응답을 보낸다.

<br>

### **NAT의 의의**

NAT의 의의는 다음과 같다.

**주소 절약**

공인 IP 하나로 많은 기기가 인터넷을 사용할 수 있다. 이 방식으로 IPv4의 주소 부족 문제를 완화했다.

**보안**

외부에서 내부 사설 IP를 직접 볼 수 없어 직접 접근이 어려워진다. 이로 인해 보안에 유리해졌다.

<br>

### **외부에서 내부 기기로 직접 접근은 불가능할까?**

필요에 따라 외부에서 내부로 직접 접근이 필요하게 될 수 있다. 그럴 때 사용하는 방법이 존재한다!

**1. 포트 포워딩 (Port Forwarding)**

가장 직접적인 방법이다. NAT 기기에 특정 포트로 들어오는 요청은 특정 기기로 전달하도록 미리 규칙을 등록하는 방식이다.

**NAT는 원래 나갈 때 기록해두고, 그 응답만 받아들이는 방식이라 외부에서 먼저 들어오는 요청은 막힌다.**

포트 포워딩은 이 규칙을 수동으로 미리 등록해, **외부에서 먼저 들어오는 요청도 특정 내부 기기로 전달되게** 뚫어준다.

**2. NAT 홀 펀칭 (Hole Punching)**

NAT의 내부에서 밖으로 나간 적이 있으면, 그에 대한 응답은 받아들이는 성질을 이용한 방식이다.

```
양쪽 기기가 각자 중간 서버(중개자)로 먼저 접속
        ↓
각자의 NAT에 "밖으로 나간 기록"이 생김 (구멍이 뚫림)
        ↓
중개 서버가 서로의 공인IP:포트 정보를 교환해줌
        ↓
그 뚫린 구멍을 통해 둘이 직접 통신
```

양쪽이 **먼저 밖으로 나가서 NAT에 구멍(hole)을 뚫어(punch)두고**, 그 **구멍을 통해 서로 연결**하는 것이다. P2P 통신(화상통화, 파일 공유, 게임 등)에서 많이 쓴다.
