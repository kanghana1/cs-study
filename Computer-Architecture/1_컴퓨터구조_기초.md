# 1. 컴퓨터 구조 기초

프로세스를 이해하기 위해서는 데이터가 어디에 어떻게 저장되는지 이해해야 한다. 이때 밀접한 연관이 있는 부분이 컴퓨터 구조이다.

<br>

## 저장장치 계층 구조

컴퓨터에는 여러 종류의 저장장치가 있다. 저장장치들은 속도와 용량이 반비례하기 때문에, 어떻게하면 효율적으로 사용할 수 있을지 고민해야 한다.

```
        ┌─────────────┐
        │   Register  │  ← CPU 내부, 가장 빠름
        ├─────────────┤
        │    Cache    │  ← CPU 근처 (L1/L2/L3)
        ├─────────────┤
        │    Memory   │  ← RAM, 실행 중인 프로그램이 올라오는 곳
        ├─────────────┤
        │    Disk     │  ← SSD/HDD, 프로그램이 저장된 곳
        └─────────────┘

```

CPU는 디스크를 직접 읽지 못하기 때문에, 디스크에서 메모리로 올려두어야 CPU가 처리할 수 있다.

<br>

## 메모리 (RAM) 구조

프로그램이 메모리에 올라오면 아래 4개의 영역으로 나뉘어 저장된다.

```
높은 주소
┌──────────────────┐
│      Stack       │  ← 함수 호출 시 생성 (지역변수, 매개변수, 복귀주소)
│    ↓ grows       │     자동 할당 / 자동 해제
├──────────────────┤
│                  │
│    (빈 공간)     │
│                  │
├──────────────────┤
│    ↑ grows       │
│       Heap       │  ← 동적 할당 메모리 (malloc, new)
│                  │     수동 할당 / 수동 해제
├──────────────────┤
│      Data        │  ← 전역변수, 정적변수
├──────────────────┤
│      Code        │  ← 실행할 코드(기계어) 자체
└──────────────────┘
낮은 주소
```

- **Code** : 실행해야 할 명령어 코드 자체를 의미한다. ex| int main(){..}
- **Data** : 전역변수, 정적변수를 저장한다. ex| int a = 0;
- **Heap** : 동적 할당
  - 프로그래머가 직접 할당 및 해제할 수 있다.
  - 때문에 관리하지 않으면 메모리 누수가 발생할 수 있다.
  - 크기를 **런타임 시점**에 결정한다.
- **Stack**
  - 지역변수나 매개변수를 저장하는 공간으로 함수 호출시 생성된다.
  - 종료되면 자동으로 사라진다.
  - 크기가 **컴파일 시점**에 결정된다.

그림을 보면 stack은 위에서 아래로, heap은 아래에서 위로 쌓아간다. 이러다가 두 영역이 충돌하는 것이 우리가 흔히 아는 **Stack Overflow**이다.

Stack이 한계를 넘으면, OS가 이를 감지해 프로그램을 강제로 종료시킨다. 요즘 OS들은 가상 메모리 기법을 써서 프로세스에게 독립된 주소공간을 줘서, 물리적으로 충돌하기 전에 OS가 개입해서 이를 막아준다.
